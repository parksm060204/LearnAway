# 1단계 — 내 자료를 분석 가능한 Markdown으로 완성

## 목적

PDF, Markdown, 전사본을 넣고 원본과 변환 결과를 비교·수정한 뒤 자료 버전과 연결해 저장한다. 로컬 원본 보관과 서버 전송은 별도 선택과 상태로 보인다.

## 구현 항목

### 입력과 식별

- PDF, `.md`/`.txt`, 전사본 입력을 단일 자료 생성 흐름에서 검증한다.
- MIME, 확장자, 파일 시그니처, 크기, 빈 파일, 손상 파일을 확인한다.
- 동일 내용 중복은 정규화된 hash와 사용자 scope로 식별한다. 이름만 같은 다른 내용은 덮어쓰지 않는다.
- 업로드·변환·저장 작업은 안정적인 job ID와 자료 버전을 갖고 취소·재시도해도 중복 자료를 만들지 않는다.

### 변환 결과 검토

- PDF 원본과 Markdown을 나란히 표시하고 페이지 번호와 절 위치를 보존한다.
- 전사본은 발화자와 입력에 존재하는 시각만 보존한다. 없는 시간정보를 만들지 않는다.
- 수식, 표, 코드 블록, 한국어가 깨지지 않는지 확인한다.
- 스캔·혼합 PDF는 추출된 페이지와 실패한 페이지를 개별 표시한다. 빈 추출 결과를 성공으로 저장하지 않는다.
- 자동 OCR이 미지원이면 지원 상태를 명확히 알리고 외부 변환 Markdown을 원본 PDF에 안전하게 재연결한다.

### 변환 실행과 전송 정책

- 변환기 인터페이스를 만들고 Python worker는 배포 가능한 worker adapter로 격리한다.
- worker의 페이지·시간·메모리·동시성 제한과 안전한 실패 응답을 유지한다.
- 로컬 전용, 서버 백업, AI 분석 전송 각각의 의미·보관기간·실패 상태를 별도로 표시한다.
- 로컬 전용 원본은 자동으로 Storage에 올리지 않는다. 서버 전송은 사용자 선택과 정책을 따른다.

## 완료 증거

- 수식 PDF, 코드 자료, 한국어 전사본에서 검토 가능한 결과를 얻거나 페이지별 실패·미지원 상태를 확인한다.
- 새로고침 후 원본과 Markdown의 ID·hash·페이지 연결이 유지된다.
- 로컬 전용 자료의 서버 업로드가 발생하지 않는다.
- 취소·재시도·동일 파일 중복 처리에서 자료나 본문이 손실·중복되지 않는다.
- 실제 운영 환경에서 worker 유무와 오류가 readiness에 반영된다.
