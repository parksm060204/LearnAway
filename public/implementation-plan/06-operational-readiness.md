# 6단계 — 운영 전환과 한 과목 완주

## 목적

한 사용자가 실제 과목 하나를 자료 입력부터 재도전과 백업까지 완주한다. 운영 상태·비용·복구를 관측할 수 있고 미지원 기능을 성공으로 오인하지 않는다.

## 운영 설정과 관측

- 학교 Gateway 실제 계정의 연결·모델 목록·오류 분류를 확인한다. 유료 생성 검증은 별도 승인된 호출·토큰·비용 범위에서만 한다.
- 사용자별 AI 요청량·토큰·지연·실패율·예산 초과와 미완료 저장·변환 작업을 관측한다.
- 로그는 key, bearer token, 답안, 강의 원문, 개인 파일 경로를 기록하지 않는다.
- 테스트·운영 데이터, 관리자 설정, encryption key를 환경별로 분리한다.
- 백업·복원은 ID, 내용 hash, 외래 연결과 충돌을 확인하고 기존 최신 자료를 덮지 않는다.
- 원격 migration은 적용 이력을 읽어 확인한다. 자동 적용하지 않는다.

## 품질 게이트와 UX

- CI에서 타입 검사, lint, 회귀·실패 시나리오, production build를 실행한다.
- 핵심 브라우저 흐름에서 로그인, 계정 전환, 저장 응답 유실, 새로고침, 좁은 화면, 키보드 접근을 확인한다.
- 메인은 시험 D-day, 오늘의 주요 복습 행동, 곡선·학습 이력에 집중한다.
- 자료 관리, 생성, 통계의 고급 옵션은 해당 작업 화면에 둔다.
- 가격·모델 성능·기억 확률을 검증되지 않은 사실처럼 표현하지 않는다.

## 최종 완주 시나리오

신규 Google 로그인 → 과목·시험일 설정 → 실제 자료 입력과 검토 → 전체 범위 분석 → 고난도 문제 검토와 승인 → 풀이와 평가 → 이력 확정 → 다음 복습 추천 → 재접속과 재도전 → 백업·복원.

## 완료 증거와 운영 범위

- 시나리오의 각 단계에 서버/로컬 영속 상태와 실제 사용자 관찰 증거가 있다.
- 서비스 연결 여부, 미지원 스캔 OCR·외부 알림 등 남은 범위를 보고서에 명시한다.
- 전체 정확도나 성적을 보장하지 않으며, 표본 문항의 검토 결과를 표본 범위로만 보고한다.
- 운영 준비 체크와 복구 절차가 실제 계정에서 확인된 뒤에만 실기능 완료로 선언한다.
