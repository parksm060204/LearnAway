# 2단계 — 긴 자료 전체 분석과 작업 재개

## 목적

자료 끝까지 분석하되 예산 한도와 사용자 선택을 지킨다. 중단 뒤에는 이미 성공한 청크를 재사용하고, 처리 범위가 실제 결과와 일치하도록 한다.

## 작업 식별

- 분석 ID는 user ID, material ID, source hash/version, 선택 페이지 범위, provider/model, prompt/schema version으로 고정한다.
- 같은 작업의 재시도는 동일 ID와 체크포인트를 사용한다. 입력이 바뀌면 새 분석 revision을 만든다.
- 계정 전환 중 이전 사용자 작업 결과를 새 사용자 캐시에 적용하지 않는다.

## 청크 실행

- 청크별 `pending/running/completed/failed/cancelled` 상태, 페이지 범위, 입력 hash, 시작·완료 시각, 출력 hash를 저장한다.
- 동시 실행과 재시도 중복을 막는 서버 claim/lease 또는 동등한 조건부 쓰기를 사용한다.
- 페이지 구간과 총 예산을 명시하고, 한도 도달 시 처리 완료·미처리 구간을 반환한다.
- 전체 성공은 모든 선택 청크가 완료되고 결과 저장 read-back까지 성공했을 때만 표시한다.
- 실패한 청크 재시도는 AI 호출만 수행하고 성공 청크 저장 실패는 저장만 다시 시도한다.

## 결과 병합과 근거

- 개념마다 자료 ID, 페이지/발화 위치, 원문 인용, 청크 ID를 보존한다.
- 중복 개념 병합 시 근거 목록을 합치고 서로 모순되는 정의는 자동 삭제하지 않고 검토 대상으로 둔다.
- 원본 자료 버전이 바뀌면 영향받는 개념·초안에 `needsSourceReview`를 설정한다.
- 모델 출력은 JSON parsing과 스키마, 참조 페이지, 필수 필드 검증을 통과해야 저장한다.

## 완료 증거

- 다섯 청크 이상 fixture에서 마지막 청크가 처리되고 UI 범위와 기록 범위가 일치한다.
- 중간 실패 후 재개 시 완료 청크의 AI 호출 수가 증가하지 않는다.
- 출력 저장 실패는 저장 재시도로 복구되고 AI 재호출이 없다.
- 취소·계정 전환·입력 버전 변경이 기존 사용자 결과를 덮어쓰지 않는다.
