# 3단계 — 대학 시험 수준 문제 생성과 검증

## 목적

강의 근거에 연결된 논술·증명·알고리즘 문제를 소량 생성하고, 생성물의 근거·정답·난도·루브릭 검증 상태를 승인 전에 분명히 보여준다.

## 사용자 선택과 설계

- 과목, 시험 범위, 연결 개념, 문제 유형, 난도, 문항 수, 예상 시간을 받는다.
- 예제 기반은 전제 변경·일반화·반례·정당화 중 어떤 전이를 할지 명세한다.
- 개념 기반은 두 개 이상의 개념 연결과 연결 이유를 명세한다.
- 숫자·표현만 바꾼 문제는 전이 문제로 승인하지 않는다.
- 처음에는 작은 batch로 제한하고 완료 문제 재사용·중복 감지를 수행한다.

## 생성 묶음과 검증

- 문제 지문, 정답, 단계별 힌트, 문제 고유의 100점 루브릭, concept IDs, source refs, 출처 인용, 생성 job/version을 하나의 초안으로 저장한다.
- 누락 점수·항목·정답·출처를 일반 텍스트나 임의 배점으로 조용히 보충하지 않는다.
- 구조 오류, 루브릭 합계 오류, 근거 인용 불일치, 정답 검토 필요, 난도 검토 필요를 구분해 초안 상태로 격리한다.
- 저장 실패 시 기존 AI 결과를 보존하고 저장만 재시도한다.
- 출처 존재, 문항의 논리적 정답성, 난도 적합성 검토를 별개 검사로 기록한다.
- 수학은 가정·정의역·경계·반례·증명 단계를 확인하고 코딩은 제한 조건·복잡도·반례를 검토한다.
- 코드 실행 검증은 격리 runner가 준비된 문제에 한해서만 제공하며 정적 모델 검토와 분리한다.

## 완료 증거

- 강의 근거로 생성한 수학 10문항과 코딩 10문항을 별도 검토한다.
- 모든 배포 후보에 출처, 답안, 유형에 맞는 100점 루브릭, 연결 개념이 있다.
- 치명적 정답 오류는 배포 세트에서 0건이며 각 검토의 방법과 한계를 기록한다.
- 실패·불완전 문항은 승인 가능 상태로 표시되지 않는다.
