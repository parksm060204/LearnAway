# 0단계 — 실사용 데이터 보호와 운영 경계 확정

## 현재 상태: 진행 중

2026-10-07 기준으로 저장 재시도 판정, 후처리 미완료 표시, PDF API 인증·입력 제한, 사용자용 데모 전체 초기화 기능 제거를 구현했다. 회귀 검사 268개, `npx tsc --noEmit`, ESLint가 통과했다. 이 검사는 mock/로컬 검증이다.

단계는 아직 완료되지 않았다. 원격 Supabase migration 목록과 실제 데이터 보존 여부를 확인할 연결 설정/자격 증명이 없고, 격리된 실제 계정과 배포 런타임의 Python/PyMuPDF4LLM 설치 여부도 확인하지 못했다. 사용자 브라우저에서 응답 유실·두 탭·계정 전환 시나리오도 실행하지 않았다. 이 확인이 끝날 때까지 이 문서와 다음 단계 진입 차단을 유지한다.

## 목적

실제 자료를 입력하기 전에 저장 완료 판정, 재시도, PDF 변환, 계정 경계, 운영 데모 기능의 위험을 닫는다. 모든 쓰기는 실제 저장소 read-back 또는 명시적인 미완료 상태로 증명한다.

## 범위와 실행 순서

### 0.1 기준 상태와 저장 경로 목록화

- 현재 HEAD와 작업 트리의 기존 변경을 기록하고, 사용자 변경을 덮어쓰지 않는다.
- `materialEditSave`, `recordMaterialServerSave`, 작업 ID·expectedVersion 생성, 후처리 장부의 호출 경로를 UI부터 DB RPC까지 추적한다.
- 성공, 응답 유실, 서버 거절, 기기 저장 실패, 계정 전환, 두 탭 충돌의 상태 전이를 표로 남긴다.
- 조회 실패와 실제 빈 결과, 로컬 원본·서버 캐시·미저장 수정은 별개 상태로 유지한다.

### 0.2 조건부 저장과 작업 소유권

- 작업 ID를 최초 서버 변경 전에 생성하고 재시도 동안 같은 ID를 유지한다.
- 최초 작업의 기준 버전을 작업 레코드에 고정하고 재시도 전 조회값으로 교체하지 않는다.
- 메타데이터가 같다는 사실만으로 완료 처리하지 않는다. 서버가 확인한 job ID, 버전, identity/hash를 함께 비교한다.
- read-back 실패·불완전 응답·알 수 없는 RPC 결과는 `pending` 또는 `verification_required`로 남기며 성공 문구를 내지 않는다.
- 계정·과목·자료 ID와 작업 시작 시 scope를 고정한다. 계정 전환 뒤에는 추가 쓰기를 중단한다.

### 0.3 후처리 장부

- 본문 저장과 후처리 상태(인덱스·원본 연결·검토 플래그 등)를 독립된 하위 작업으로 기록한다.
- 일부 하위 작업 실패 시 부분 완료를 표시하고 실패 항목과 재시도 동작을 보존한다.
- 사용자 입력과 원본은 모든 하위 작업의 read-back 검증이 끝날 때까지 유지한다.
- 재시도는 완료된 하위 작업을 다시 실행하거나 AI를 재호출하지 않는다.

### 0.4 PDF 변환 API 경계

- 인증을 multipart 파싱, 파일 버퍼화, Python 프로세스 생성보다 먼저 검사한다.
- 파일 크기·페이지 수·페이지당 텍스트 또는 전체 출력 크기·실행 시간·동시 작업 수를 서버에서 제한한다.
- 파일 확장자만 신뢰하지 않고 PDF 시그니처와 파서 결과를 확인한다. 임시 파일은 격리 경로에서 만들고 모든 종료 경로에서 제거한다.
- Python 부재, timeout, 잘못된 PDF, 너무 큰 파일은 안전한 코드와 사용자용 메시지로 반환한다. 경로, stack, 서버 환경 값은 응답에 넣지 않는다.
- 운영 런타임에 Python과 PyMuPDF4LLM이 설치되는지 확인한다. 보장할 수 없으면 readiness에 미지원 상태를 표시한다.

### 0.5 데모 데이터와 운영 환경

- 운영 설정에서 사용자 데이터 전체를 INITIAL fixture로 덮는 동작을 제거한다.
- fixture는 테스트 전용 저장소·계정에서만 로드한다. 사용자가 직접 선택한 체험 자료는 실제 사용자 자료와 혼합하지 않는다.
- 신규 계정 초기 상태가 빈 계정인지, 기존 계정의 자료·답안·학습 이력이 유지되는지 확인한다.

### 0.6 원격 마이그레이션 상태

- 읽기 전용으로 로컬 migration과 원격 적용 목록을 비교한다.
- 원격 확인 실패, 권한 부족, 미적용을 서로 다른 상태로 표현한다. 임의 fallback이나 마이그레이션 적용은 하지 않는다.
- 새 migration의 적용이 필요한 기능은 운영 준비 미완료로 표시한다.

## 완료 증거

- 서버 저장 성공/응답 유실, 후처리 실패, 로컬 quota 오류, 두 탭 충돌, 계정 전환 시나리오가 실제 호출 경로에서 검증된다.
- 비로그인 PDF 요청이 Python 실행 전 차단되고 업로드·페이지·시간·동시성 상한이 서버에서 적용된다.
- 신규 실제 계정은 비어 있고 기존 실제 데이터는 삭제·fixture 교체 없이 유지된다.
- 원격 migration 상태를 확인하고, 결과 또는 확인 불가 이유를 기록한다.
- 부분 실패는 완료로 오인되지 않고 사용자가 복구할 수 있다.

## 중단 기준

원격 DB 자격 정보, 격리된 테스트 계정, Python 운영 런타임 중 하나라도 없으면 해당 검증은 미완료로 둔다. 데이터 삭제, migration 적용, 배포는 별도 승인 없이 실행하지 않는다.
