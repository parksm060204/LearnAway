# 4단계 — 풀이·실제 평가·재도전

## 목적

학생 답안, 사용한 힌트, 풀이 이유, 문제 버전을 함께 보존하고 실제 문제 기준으로 부분 점수와 근거를 반환한다. 평가 실패를 학습 완료로 바꾸지 않는다.

## 고정 평가 기준

- 서버의 승인 문제·루브릭을 평가 기준으로 조회하거나, 확인된 immutable version snapshot을 함께 저장한다.
- 평가 대상 problem ID, subject/concept scope, version이 일치하지 않으면 AI 호출 전에 거부한다.
- 제출 시 답안·풀이 이유·힌트 수·문제 버전의 스냅샷을 고정한다. 이후 문제 수정이 과거 결과를 바꾸지 않는다.
- rubric 결과 ID, 항목별 점수, evidence quote, deduction reason을 검증하고 합계를 직접 계산한다.
- 동치 풀이·정당한 부분 점수·잘못된 증명·경계 조건 누락을 포함한 고정 검증 세트를 둔다.

## 실패·저장·재도전

- 평가 실패, 평가 성공 후 서버 저장 실패, 응답 유실을 각각 표시한다.
- 평가 결과가 만들어진 뒤 저장 실패하면 동일 평가 snapshot을 저장만 재시도한다. AI를 재호출하지 않는다.
- 서버 확인 전 이력 완료나 복습 곡선 갱신을 표시하지 않는다.
- retry ID와 payload가 일치할 때만 idempotent 성공으로 처리한다. ID 충돌 내용은 보존하고 conflict로 반환한다.
- 새로고침 후 답안 draft를 복원하고 탭별 draft가 섞이지 않게 한다.
- 모의시험 마감·제출 잠금·두 탭 충돌에서는 답안을 보존하고 사용자 선택을 요구한다.

## 완료 증거

- 정답·부분정답·오답 세트에서 항목별 근거와 총점이 기준 정답표와 일치한다.
- 실패한 평가는 Attempt/ReviewEvent/계획 완료에 반영되지 않는다.
- 저장 응답 유실 뒤 재시도해도 attempt/event가 중복되지 않고 내용 충돌은 거부된다.
- 같은 문제의 새 버전에서도 과거 답안·평가와 새 답안 비교가 가능하다.
- 브라우저 새로고침·마감·충돌 테스트에서 입력을 잃지 않는다.
