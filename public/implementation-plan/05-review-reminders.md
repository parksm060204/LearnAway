# 5단계 — 시험일까지 이어지는 복습과 실제 리마인드

## 목적

검증된 실제 학습 이벤트만 복습 모델과 오늘 할 일에 반영하고, 시험일과 가용 시간에 맞는 다음 복습을 제안한다. 추정치를 성적 보장으로 표현하지 않는다.

## 복습 데이터와 설명

- 기존 retention model과 개인화 규칙을 유지한다. 입력은 서버 확인이 끝난 실제 이벤트로 제한한다.
- 복습 이유를 시간 경과, 낮은 점수, 힌트 의존, 반복 오류, 시험 임박으로 구분한다.
- 곡선의 학습점을 선택하면 원래 자료, 당시 문제 버전, 답안, 채점 근거와 피드백을 연다.
- 완료·미룸·건너뜀을 각각 보존하고 미완료 항목을 자동 완료하지 않는다.
- 가용 시간과 문항 분량 안에서 일별 계획을 만든다. 휴식일과 시험 종료 상태를 명시한다.
- 점수·기억 확률·성적은 추정치임을 표시하고 검증되지 않은 상수를 보편값으로 광고하지 않는다.

## 앱 밖 알림

- 앱 안 오늘 복습 목록을 먼저 완성한다. 이후 이메일 또는 Web Push 중 한 채널을 명시적으로 선택한다.
- 구독 동의·취소·계정 소유권·KST 시간대·중복 방지 idempotency key·예약 상태·재시도·발송 기록을 구현한다.
- 알림 본문에 강의 원문·답안·API 키를 넣지 않는다.
- 예약/전송 실패를 UI와 작업 장부에 표시한다. 앱을 열어 둔 타이머를 서버 예약 발송이라고 표시하지 않는다.

## 완료 증거

- 실제 풀이 이벤트가 한 번만 곡선·계획에 반영되고 재시도는 복습 회차를 늘리지 않는다.
- 시험일 변경, 날짜 경계, 미룸, 휴식일의 계획 갱신을 검증한다.
- 곡선에서 과거 풀이 snapshot을 다시 열 수 있다.
- 동의한 테스트 계정에 예약 알림이 한 번 전달되고 해제 후에는 전달되지 않는다.
- 예측이 학습 우선순위이며 성적 보장이 아니라는 표현을 화면에서 확인한다.
