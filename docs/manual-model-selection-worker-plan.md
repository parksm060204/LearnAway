# 사용자 직접 AI 모델 선택

## 사용자 지시 및 역할

사용자는 난이도 자동 판단 로직이 없으므로 AI 모델을 직접 선택할 수 있도록 요청했다. 기존 난이도(Level 1~3 DeepSeek / Level 4~5 Sonnet) 강제 분기를 사용자 명시 선택으로 교체한다. 주 담당은 계획과 검토만, 구현/검증은 Antigravity gemini-4-hydrogen-medium 워커가 전담한다. 지금까지의 UI/저장 복구 변경과 사용자 변경을 전부 보존한다. 커밋/푸시/배포/유료 실제 AI 호출은 하지 않는다.

## 사전 확인

AGENTS.md, 현재 코드와 diff, docs/difficulty-model-routing-report.md, supabase/migrations의 ai_connections/RLS/크레딧 작업 식별 및 복구 관련 SQL, 로컬 Next.js 가이드를 읽는다. lib/aiModelPolicy.ts, lib/aiCredentials.ts, lib/aiClient.ts, 5개 문제 기반 API, ai-connection API, 문제 생성/풀이/모의시험/논리강화 클라이언트, 기존 taskId/복구 토큰 계산을 확인한다. 기존 자동 분기 구현을 활용하되 더 이상 난이도로 모델을 강제하지 않는다. 이전 보고서는 최신 정책이 사용자 선택으로 변경됐음을 명시하여 혼동을 없앤다.

## 사용자 경험

- AI 설정에서 기본 모델을 고르고 저장할 수 있게 한다. 기존 ai_connections.model과 model-only PUT/touch_ai_connection 경로를 활용한다. 연결된 사용자가 API 키를 다시 입력하지 않고 모델을 변경할 수 있어야 한다. 서버 모델 목록 읽기용 기존 검증을 재사용한다. 모델 목록/설정 조회 실패를 빈 목록/미등록으로 처리하지 않는다. 서버 저장 전 완료 문구를 보여주지 않는다. 실패 시 선택과 재시도 경로를 보존한다.
- 문제 생성과 답안 채점 시작 화면에서 이번 작업에 쓸 모델을 직접 선택할 수 있도록 라벨 있는 컨트롤을 제공한다. DeepSeek(deepseek-v4.1-flash) / Sonnet(claude-sonnet-5-5)을 이름과 정확한 ID로 구분한다. 기본은 저장된 사용자 모델, 미등록 체험의 기존 운영자 기본 모델, 또는 DeepSeek다. 기존 비학교 제공자는 임의로 학교 모델을 끼워 넣지 않고 기존 단일 제공자 동작을 보존하고 선택 불가 이유를 알린다.
- 모의시험 채점, 논리 질문/전이 문제/품질 검토처럼 별도 선택 컨트롤이 없는 관련 작업은 저장된 기본 모델 또는 해당 흐름에서 명시한 선택을 일관되게 사용한다. 모든 경로에서 난이도 강제 분기가 없어야 한다. 자동 선택 안내 문구를 제거/교체한다.
- 최근 만든 공통 UI, 한국어 표현, 모바일/키보드 접근성/입력 라벨을 유지한다. 실제 유저가 이해하는 모델 선택만 표시하고 내부 구현 정보를 제품 설명에 늘어놓지 않는다.

## 서버 정책과 안전성

- 우선순위: 검증된 이번 요청의 명시 선택 > 저장된 사용자 모델 > 기존 허용된 운영자 기본 설정. 모델이 없으면 DeepSeek 기본. 요청 모델의 타입/길이/허용 여부를 검증한다. 학교 요청의 이번 선택은 DeepSeek와 Sonnet(기존 환경 override를 유지할 경우 서버에서 제공한 허용 ID)에 한정하고 사용자 키/운영자 키에서 실제 모델 목록으로 권한을 검증한다. URL/키/제공자를 클라이언트가 바꿀 수 없게 한다.
- 모델 옵션은 실제 선택된 모델을 기준으로 한다. DeepSeek minOutputTokens 등을 Sonnet에 복사하지 않는다. 선택한 모델 미지원/권한 거부/조회 실패에는 명확한 오류를 반환하고 다른 유료 모델이나 DeepSeek로 대체하지 않는다. 사용자 키와 운영자 키 우선/권한/체험 예산은 기존 정책을 보존한다. 검증 전 예약을 최소화하며 예약이 있으면 기존 환급/복구 규약을 지킨다.
- 기존 DB 소유권 확인/조회 실패 차단은 유지한다. 난이도가 더 이상 모델 선택 근거는 아니어도 기존 문제 소유권 검증을 삭제해서는 안 된다. 로컬 초안과 서버 문제 구분도 보존한다.
- 모델을 선택할 수 있게 되면 동일 입력의 다른 모델 호출은 새 작업이어야 한다. 클라이언트의 taskId/recovery refs/저장 retry 상태와 서버의 canonical inputIdentifier/taskId를 함께 검토하고 선택 모델 변경 시 이전 캐시나 결과와 혼동하지 않게 한다. 생성 도중 모델을 바꿔도 진행 중 요청/결과는 시작 시 모델로 유지한다. 저장 재시도는 원래 결과·모델·서명 토큰을 고정하고, 기본 모델을 바꿔도 AI를 재호출하거나 결과를 버리지 않아야 한다. 이전 토큰·결과 복구는 명시적 레거시 호환으로 유지한다.
- 기존 telemetry는 실제 응답 모델을 기록하고 미확인 단가는 미확인으로 표시한다. 과거 문제/채점/시험 스냅샷을 변경하지 않는다. DB 마이그레이션은 가능한 피하고 필요시 후속 파일만 추가한다. 새 의존성 추가를 피한다.
