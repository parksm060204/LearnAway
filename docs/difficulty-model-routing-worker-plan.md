# 난이도별 AI 모델 선택 작업 지시

## 역할 및 요청

주 담당은 계획/검토만 담당하고, 구현과 검증은 Antigravity gemini-4-hydrogen-medium 워커가 담당한다. 사용자는 쉬운 문제는 DeepSeek, 어려운 문제는 `55sonnet`으로 사용하도록 요청했다. 정확한 `55sonnet` 모델명/BAZE 모델 ID는 주 담당이 사용자에게 질문한 상태이며 아직 미확정이다. 임의로 Sonnet 버전이나 모델 ID를 만들어 넣거나 다른 모델로 대체하지 않는다.

## 우선 진행

AGENTS.md, README와 관련 문서, AI/크레딧 마이그레이션, 로컬 Next.js 가이드를 읽는다. 현재 코드와 미커밋 변경을 확인하고 전부 보존한다. 앞서 UI 개선과 시험 답안 복구 관련 변경이 존재한다. 검토할 주요 파일은 lib/aiConfig.ts, lib/aiClient.ts, lib/aiCredentials.ts, lib/trialCredits.ts, lib/aiCostTelemetry.ts, app/api/ai-connection/route.ts, app/api/generate-problems/route.ts, app/api/evaluate-answer/route.ts, app/api/transfer-problem/route.ts, app/api/review-problem-quality/route.ts 및 관련 클라이언트다.

정확한 Sonnet 모델이 미확정인 동안에는 구조 조사, 모델 ID와 독립적인 공통 선택기/검증/테스트 준비를 진행한다. 모델별 요청 옵션과 하드 모델 기본값 및 활성화는 모델 ID가 확인된 뒤 진행한다. 코드에 `55sonnet`을 유효한 ID처럼 입력하지 않는다. 확인 없이는 고난도 요청이 DeepSeek로 조용히 처리되거나 임의 유료 모델로 호출되지 않게 한다. 결정이 필요한 시점에 orchestration ask로 주 담당에게 확인하고 턴을 종료한다.

## 예정 정책 및 구현 기준

- 기존 Level 1~5 기준으로 Level 1~3은 학교 BAZE Gateway의 deepseek-v4.1-flash, Level 4~5는 사용자가 지정할 Sonnet 모델이다. 경계 3/4를 명시적 공통 정책으로 만들고 안내한다.
- 적용 중심은 문제 생성과 답안 채점이다. 전이 문제/품질 검토/문제 관련 추가 AI 작업도 조사해 같은 문제 난이도를 사용해야 하는 곳을 식별하고 누락되지 않도록 범위를 보고한다. 자료 개념 분석처럼 문제 난이도가 없는 작업은 기존 DeepSeek 동작을 보존한다.
- 기본 경로는 기존 학교 BAZE Gateway와 같은 사용자의 키다. Sonnet이 그 Gateway에서 제공되는지 검증할 수 있어야 한다. 별도 Anthropic 키나 제공자로 자동 전환하거나 다른 제공자의 키/URL을 섞지 않는다. 비학교 제공자 기존 설정이 있으면 그 호환 동작을 보존하고 적용 범위를 명확히 한다.
- 서버에서 모델을 선택한다. 클라이언트가 임의 모델명을 주입할 수 없게 한다. 생성은 검증된 요청 난이도, 채점/기존 문제 작업은 DB의 권한 검증된 문제 또는 풀이 당시 스냅샷의 난이도를 사용한다. 클라이언트 난이도 조작으로 고난도 채점을 낮추거나 상향하지 못하게 한다. 레거시 난이도는 기존 매핑과 과거 풀이 스냅샷을 보존하며 처리한다.
- 기존 제공자·키·주소·모델을 하나의 AiConfig로 처리하는 구조를 활용한다. 기존 암호화 키/RLS/사용자별 키 우선 정책을 지킨다. 새 설정을 노출할 필요가 있으면 안전한 모델 ID/정책 정보만 노출한다.
- 모델별 구조화 출력 및 토큰 옵션을 확인한다. DeepSeek용 16000 minOutputTokens 등을 무작정 Sonnet에 복사하지 않는다. 실제 지원이 검증되지 않은 옵션은 보내지 않는다.
- 모델 미지원/권한 부족/키 조회 실패/목록 조회 실패를 명확히 실패로 처리하고 유료 다른 모델 fallback을 하지 않는다. 실패 전 크레딧 예약을 최소화하고 예약이 존재하면 누수 없이 기존 정산/환급 경로로 처리한다.
- idempotency, 저장만 재시도, 결과 캐시/응답 유실 복구를 보존한다. 저장된 결과 복구 시 모델 선택 변경 때문에 AI를 다시 호출하지 않는다. 새 작업의 요청 식별과 실제 모델 기록의 상호작용을 검토한다. 사용량과 비용 모델명은 실제 AI 응답에 기반하고, 확인되지 않은 Sonnet 단가를 추정해 사실처럼 저장하지 않는다.
- UI에는 최근 만든 공통 디자인을 유지하며 난이도별 사용 모델을 문제 생성 화면/설정 등 필요한 곳에 짧게 안내한다. 앱 모델 변경과 워커 모델은 별개다.
- 불필요한 의존성/DB 마이그레이션을 피한다. 필요시 배포된 마이그레이션을 수정하지 말고 새 마이그레이션만 추가한다. 사용자 로컬 원본, 답안, 과거 기록을 초기화하지 않는다.
